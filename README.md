# Make Me Menu Planner

Семейное приложение для планирования меню и списка покупок.

## Проблема

Каждые выходные семья тратит значительное время на:
- Составление меню на неделю
- Расчёт количества продуктов
- Составление списка покупок

## Решение

Приложение автоматизирует планирование: генерирует меню на неделю с учётом истории блюд и сложности, автоматически формирует список покупок.

## Архитектура

Monorepo (pnpm workspaces):

```
apps/backend   — Express + Node.js + TypeScript + Prisma
apps/frontend  — React + TypeScript + Vite
packages/shared — общие типы, enums, DTO
```

База данных: PostgreSQL

## Запуск

```bash
# Установка зависимостей
pnpm install

# Запуск БД (Docker)
docker-compose up -d

# Миграции
pnpm --filter backend prisma migrate dev

# Seed
pnpm --filter backend prisma db seed

# Разработка (frontend + backend)
pnpm dev
```

## Требования

- Node.js >= 20
- pnpm >= 9
- Docker (для PostgreSQL)

## Библиотека рецептов UniTools

В каталоге доступны разделы «Постоянное меню», «Хочу попробовать» и «Отклонено».
Кнопка **Импортировать UniTools** добавляет 501 рецепт из закреплённого JSON
версии 2.0.0. Интернет при импорте не нужен. Повторный запуск не создаёт дубли
и не перезаписывает ваши изменения, оценки и решения. Удалённые импортированные
рецепты запоминаются в списке исключений и не возвращаются при повторном импорте.

После обновления кода:

```bash
pnpm --filter @make-me-menu/shared build
pnpm --filter @make-me-menu/backend exec prisma generate
pnpm --filter @make-me-menu/backend exec prisma migrate deploy
pnpm --filter @make-me-menu/backend db:import:unitools
```

CLI импорта читает `apps/backend/.env`. Перед применением миграций сохраните
резервную копию нужной БД. `db:seed` для обновления не нужен: старый seed очищает данные.

Недельное меню автоматически составляется только из постоянных блюд. Для пробы
откройте замену блюда в недельном меню: там есть поиск и фильтр «Хочу попробовать».
В карточке рецепта нажмите **Приготовили — оценить**, поставьте общую семейную
оценку 1–5, добавьте заметку и выберите дальнейшую судьбу блюда.
Просмотр меню больше не создаёт записи о приготовлении.

Рецепт, связанный с меню, можно отклонить с сохранением истории; окончательное
удаление доступно для рецептов без таких связей. Гарниры, десерты, хлеб, закуски,
соусы, салаты и напитки импортируются без автоматического назначения на приём
пищи: перед планированием отметьте подходящий приём в редакторе.

КБЖУ UniTools указаны **на одну порцию**. Старые блюда сохраняют прежнюю основу
**на 100 г**. Основа видна в карточке и выбирается в редакторе; импорт не делает
необоснованного пересчёта. Ингредиенты «по вкусу» сохраняются с пустым количеством
и попадают в закупки отдельными строками. Зубчики, щепотки, веточки и ломтики
не превращаются в граммы. Для `linear` используется отношение порций, для `fixed`
количество сохраняется, а для `damped` приложение использует квадратный корень
из отношения порций — это явно выбранное правило приложения.

Источник: [UniTools](https://theunitools.com/ru/data),
лицензия [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/).
Исходный JSON и уведомление об атрибуции находятся в `apps/backend/src/data`.
Фотографии не импортируются.

## Проверки

```bash
pnpm test
pnpm build
pnpm --filter @make-me-menu/frontend lint
```

Обычные тесты не обращаются к БД. Старый `tests/api/integration.test.ts`, который
удалял меню текущей недели в подключённой базе, исключён из запуска.

Новые интеграционные тесты используют отдельную БД **в существующем контейнере**:

```bash
# Один раз; имя контейнера и роль замените на свои.
docker exec family-menu-db createdb -U family make_me_menu_unitools_test
pnpm --filter @make-me-menu/backend test:integration
```

Runner берёт подключение из `.env`, заменяет только имя БД на
`make_me_menu_unitools_test`, применяет миграции и запускает сценарии импорта,
планирования, закупок, оценок и API. Тестовая БД очищается в начале проверки;
запуск на семейной БД блокируется конфигурацией и отдельной проверкой в тесте.
